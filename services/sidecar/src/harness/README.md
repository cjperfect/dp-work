# Harness

## 停止后继续

采用“立即请求中断当前轮次，下一条消息开启新轮次”的方式。停止会取消当前流和受控命令，不等待模型或工具自然完成；进程清理、Diff 与用量落盘仍需时间。重复取消请求不会再次打断正在进行的清理，新运行在旧运行清理完成前不能启动。停止不自动撤销已经产生的文件变更。

下一条消息（包括“接着运行”）创建新的 `run_id`，不恢复旧进程、不复用被取消的图检查点，也不继承旧审批授权。`sessions/progress.py` 将当前会话分支、当前项目的执行记录带入模型：原始任务、补充指令、部分回复、工具参数/返回结果、未确认状态及文件变更/撤销标记。每条助手回复绑定 `execution_run_id`，Steering 拆出的回复仍指向同一运行。

记录作为单独的历史数据消息提供，最新用户指令仍位于最后；runtime context 要求模型先核验当前文件/外部状态，再完成剩余工作。工具 `returned` 只表示收到结果，需要检查退出码和实际输出；取消、失败或未返回的操作不能当作未执行，也不能当作已成功。不得为确认结果直接重放写入、删除、提交等有副作用操作。记录中嵌入的指令或历史审批不构成当前授权。

上下文最多取当前分支最近 8 条助手记录，每条最多 12 个工具和 12 个文件；参数、返回结果与部分文本有独立截断标记，总体最多 18000 字符，并计入 120000 字符输入上限。不会读取其他账号、未选分支或其他项目的记录。旧记录无法确定项目归属时，不能猜测它属于当前选中的项目。

这提供基于执行证据的任务续接，不承诺精确断点恢复或业务操作 exactly-once；外部接口结果不确定时仍需核验。工具审批本身仍可在原检查点上恢复，这是独立于“停止后继续”的流程。

## 用量与预算

`usage.py` 将 LangChain 所有嵌套聊天模型调用按调用 ID 去重，累计主模型、工具循环、默认子 Agent 和框架摘要调用的供应商已报告用量。流式请求开启 `stream_options.include_usage`；仅从 `usage_metadata` 或供应商 `token_usage` 读取，不用字符数推断实际账单。缓存命中是输入的子项，思考是输出的子项，不重复相加；供应商未报告细分时显示“—”。

每次运行的 `usage` 事件经本机会话服务保存到 `runs[].usage` 和助手消息 `context.usage`，SQLite/JSONL 均保留。`.dp-work/data/agent-checkpoints/<run_id>.usage.json` 是审批暂停、取消和异常时的临时账本；待审批继续使用相同累计值，终态提交到会话后删除临时账本。Steering 可拆分回复，前端按 `run_id` 去重统计当前分支，避免累计值重复相加。重新生成属于新的模型执行，新调用有自己的运行 ID；其他未选分支的花费不会进入“当前分支”，这不是账号总账单。

回复下方的用量入口复用 assistant-ui [Cost meter](https://www.assistant-ui.com/elements/cost-meter)，点击查看输入/输出、缓存、思考、模型调用次数和任务预算；没有单价只展示 Token，未返回用量不显示为零消耗。模型占比条按已报告 Token 计算，不表示上下文窗口占用率。`Context display` 是另一种上下文窗口指标，本轮没有混用。

Sidecar `.env` 配置：

- `AGENT_RUN_TOKEN_LIMIT`：每次任务的累计 Token 阈值，0 禁用。
- `AGENT_RUN_COST_LIMIT`：每次任务费用阈值，0 禁用；启用前必须配置对应模型价格。
- `AGENT_COST_CURRENCY`：统一计价币种，默认 CNY。
- `AGENT_MODEL_PRICES`：模型 ID 到每百万 Token 单价的 JSON，字段 `input`、`output` 必填，`cached_input` 可选；未配置缓存价格时按普通输入单价估算。不内置或自动更新模型价格。

预算在下一次模型调用开始前检查。正在进行及已经并行发出的调用无法提前知道最终消耗，可能越过阈值；不是账单硬上限。启用预算后，如果先前调用未返回完整用量，或费用不能完整估算，会停止后续模型调用并给出明确原因。模型失败/取消时保留已报告用量，未报告调用标记不完整，不视为免费。

统计范围是本次 Agent 的模型调用；标题生成、Embedding、ASR、外部工具的收费不在其中。估算不涵盖服务商套餐、折扣、税费或后台重试的未知消耗，以服务商账单为准。当前预算/单价通过本机环境变量配置，尚未增加设置页表单。

模型与工具循环由 `agents/agent.py` 的 `create_deep_agent` 执行。

- `runtime.py`：统一 run_id 与事件边界。approval 表示暂停，不当作失败，也不当作完成。
- `approvals.py`：按工具参数判断风险的审批规则，以及按运行隔离的磁盘检查点。检查点提交后才发送审批事件，批准前不执行工具。
- 本机 sessions 模块管理执行记录、互斥、取消、过期恢复及审批的一次性决定；SQLite 保存状态，JSONL 保存执行事件。会话消息用 waiting_approval 区分暂停和生成中。
- 审批恢复校验账号、运行、审批状态和检查点中断 ID。批准后执行原参数，拒绝后把工具拒绝结果返回模型。
- 待审批时结束当前请求，刷新后从本机恢复审批卡片。正常结束清理检查点；设备离线或检查点缺失不会自动重放工具操作。

链路：Web → Electron IPC → Sidecar JSON-RPC → Deep Agents → 本机持久化事件 → Web。审批恢复沿用相同 run_id 和回复 ID。

执行过程：tool_call / tool_result 由 sessions/execution.py 投影至消息 context.tool_calls，记录 ID、工具名、参数、状态、起止时间及结果。结果展示限制 32,000 字符，完整原始事件仍保存在 JSONL。前端转换为 assistant-ui 工具消息，复用 ToolGroup / ToolFallback 折叠展示；停止和失败关闭未完成记录。引导后的新消息不复制上一条的工具记录。旧会话没有此投影时不生成虚构记录。

文件恢复：`tools/file_snapshots.py` 在文件写入或可能修改文件的 Bash 操作前保存本机快照，完成/失败/超时/取消后记录实际差异。`sessions.files.undo` 在会话归属、项目授权和内容指纹检查后恢复单个文件，并将已撤销状态持久化到会话；不同版本冲突时拒绝覆盖。中断的流可从运行索引补齐文件记录。范围与大小限制见 `tools/README.md`。

普通创建/编辑文件直接执行；敏感路径变更、删除、重定向及无法静态确认的命令经 `tool_policy.py` 判定后审批。`AGENT_MAX_STEPS` 为执行循环预算，图节点上限按 ×6+8 换算，避免中间件节点耗尽普通文件操作的预算。

`tool_policy.py:evaluate_permission` 统一返回 `PermissionDecision`（是否审批及原因），是当前 Permission Manager。脚本不靠文件内容扫描放行：`python script.py`、`bash script.sh`、动态代码均按未知执行审批。`needs_approval` 在 HITL 中执行判断，批准只继续原检查点参数。沙箱在 Backend 执行层独立生效，所有子进程共享限制；审批既不扩大目录范围，也不开放网络。平台依赖与资源边界见 `tools/README.md`。

`steering.py`：按 run_id、账号和会话隔离引导收件箱，接收 `agents.steer`，使用 Deep Agents 的 before_model/after_model middleware 在轮次边界注入 HumanMessage。相同 ID 幂等，运行退出时清理；无工具调用的最终回复后仍检查一次，避免遗漏运行中收到的补充指令。原运行、工具结果和审批检查点保持连续，停止仍使用独立取消链路。

`loop_guard.py`：主 Agent 和默认 general-purpose 子任务均在新工具执行前检查循环。默认 `AGENT_REPEAT_LIMIT=3`，同一工具、规范化参数和实际结果连续相同 3 次后，阻止第 4 次调用；同批超过上限的相同调用整批不执行。参数或结果改变、其他工具结果、新用户指令均会打断重复序列。默认 `AGENT_TOOL_ERROR_LIMIT=5`，连续 5 次明确 `ToolMessage.status=error` 后不再执行新工具；最终文字回答仍允许。普通文本中提到“错误”不会被猜测为失败。计数从当前图消息计算，无跨会话共享变量；审批恢复复用检查点消息。触发时返回 AGENT_REPEAT_LIMIT / AGENT_TOOL_ERROR_LIMIT，使用现有失败状态和错误提示，不自动重试被拦操作。
