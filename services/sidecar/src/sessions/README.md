# 本地会话存储

参考 Codex 的混合存储职责划分，不复制其私有文件格式。

```text
.dp-work/
├── sessions/<user-id>/<thread-id>.jsonl     # 会话事件源
├── data/users/<user-id>/state.sqlite3      # 元数据、消息分支、运行、审批及投影游标
├── data/agent-checkpoints/<run-id>.sqlite3 # LangGraph 执行检查点
└── memories/<user-id>/                    # 长期记忆独立空间，目前预留
```

开发环境使用仓库 `.dp-work`；安装版由 Electron 设置 `DP_DATA_DIR`，根目录为用户主目录的 `.dp-work`。`storage.py` 管理本机文件，`service.py` 管理会话与执行，`schemas.py` 校验消息图。

## 数据职责

- JSONL：追加保存消息变更、路径与分支变更、模型回复、工具调用和结果、引导、审批及运行终态。每条记录含 `schema_version/session_id/ordinal/timestamp/type/patch`，执行事件另有 `payload`。正文增量按秒合并；不是逐 token 强制刷盘。
- SQLite：`projects` 保存项目名称、目录及设备关联；`threads` 为会话状态，`metadata_json` 用于列表查询；`thread_items` 保存消息和父节点，`thread_turns` 保存运行；`thread_history_projection_state` 保存已投影序号和字节位置。审批和待生效引导也在会话状态内，属于可重建投影。
- Memory：跨会话长期知识独立于聊天日志。目前仅建立隔离目录，不自动提取、召回或向提示词注入长期记忆。
- LangGraph Checkpointer：沿用独立 AsyncSqliteSaver。待人工审批的执行可恢复；其他中断可通过发送“接着执行”从原节点恢复，工具结果不明确时阻止自动重放。它不是聊天列表的数据来源。

## 一致性与恢复

Sidecar 统一拥有会话写入。文件与 SQLite 工作在线程中执行，避免阻塞 ASR 和模型流。线程锁及 SQLite `BEGIN IMMEDIATE` 串行化写入，WAL + FULL 同步；先 fsync JSONL，再提交 SQLite。写入失败对调用方报错。

每次读取或修改先检查日志尾部，只重放游标之后的数据。SQLite 事务失败后可补齐索引，删除 SQLite 后也能重建会话、分支、运行和审批。仅截断没有换行符的未完成末行；完整记录损坏或序号异常会报错，不静默丢弃。

消息和草稿使用 `expected_revision`，运行中禁止修改消息或工作目录。会话列表仅显示至少有用户消息及成功 AI 回复的会话；失败首轮仍可通过当前 ID 恢复。标题生成规则保持不变。

停止会取消原执行任务并等待清理，保留最新已收到正文。重启后的非审批运行在读取时标为 interrupted；保留有效检查点的任务会在当前分支最后一条回复提示发送“接着执行”；收到续接指令时先检查本机最新任务状态。危险工具审批一次性领取，使用原 run_id 和 checkpoint 恢复。引导保持同一图与工具结果，在轮次边界追加新的消息分支。

删除先提交逻辑墓碑，再原子替换 JSONL 为不含正文的墓碑记录，同时清理消息索引。墓碑参与索引重建，旧导入不会使删除的会话复活。旧 PG 表已由 API 迁移 0022 删除；独立离线备份不会随本地会话删除自动清理。

## 通信与边界

当前客户端按模块分流：账号、会议和知识库请求远程 API，其余业务地址由 Axios 本地适配器转换为 Electron IPC，不会发送到云端。Main 只允许固定业务路径映射至语义 RPC，注入已验证的本地用户和设备，不开放任意方法或任意 URL。JSON 和 SSE 均通过 IPC 传递，取消沿 Main → JSON-RPC → Python Task 传播。

纯浏览器没有原生桥接，本地功能会提示需要桌面端，不回退至云端会话存储。首次登录需要联网验证；本机缓存已验证凭证摘要后，相同登录可在 API 离线时恢复本地功能。账号切换或退出会停止旧调用。

关联知识库时，Main 只向远程知识库申请短期检索能力令牌，提交知识库 ID，不提交聊天历史。Sidecar 的检索 Tool 再按限定范围访问云端知识库。会议纪要、ASR、解析和向量化仍可经云端任务通道交给本机执行；云端/Main 双方白名单均只允许这两类模块，不能远程触发聊天、设置、技能或连接器。

旧 PG 会话已迁入本地，迁移 0022/0024 删除旧表；恢复工具 `scripts/import_pg_sessions.py` 优先保留本地修改和墓碑。前端未发送队列仍在按账号隔离的 localStorage，属于本地数据。

测试：`cd services/sidecar && .venv/bin/python -m pytest tests/sessions -q`。

## 本地项目

`projects.py` 管理 `data/users/<user-id>/state.sqlite3` 的 projects 表；项目名称、路径、设备 ID、创建/更新时间、删除状态只在该账号本机保存。Electron 原生选择器仍负责 `data/projects.json` 的授权记录，Sidecar 不接受网页提供的任意目录作为授权。

只有经过本机授权且已登记的项目可关联会话或启动正式聊天。删除项目先检查所有关联会话均无运行或待审批，依次提交 JSONL 解除关联，再提交项目墓碑；中断后可重试，用户目录不删除。再次原生选择同一目录可重新登记。

项目表本身是本地元数据源，不从会话 JSONL 重建；备份应同时包含本地 SQLite 和 data/projects.json。PG agent_projects 表由迁移 0024 删除，旧数据已备份并迁入本地；云端 devices 表仍用于执行设备在线连接，不保存项目目录。

## 精选长期记忆

长期记忆由后台自动提取关键信息，不把每条聊天、工具输出或全文摘要都加入记忆。前端设置页不再提供记忆板块或手动管理入口；历史手动记忆及其保护规则保留。记忆按用户、Agent、项目隔离。正文以本机明文保存于 `memories/<user-id>/memory.sqlite3`，不要填写密码、API Key 等凭证。

新一轮执行最多加载 8 条、5000 字符的启用且未过期记忆；同名约定按项目、Agent、用户的优先级去重。当前用户指令优先，记忆不能扩大工具权限或跳过审批。会话仅记录本轮载入记忆的 ID、标题、范围和版本等引用。每轮以最新用户消息做语义检索，先按账号、Agent、项目过滤，并按范围优先级处理同名约定，再以余弦相似度选取相关记忆。

### 后台生成

`memory/worker.py` 随 Sidecar 启停，默认每 60 秒扫描一次，选择最近 30 天更新、已经空闲 6 小时且有完整问答的会话。运行中、待审批、含未发送草稿的会话不处理；问候和过短内容不调用模型。每批最多 4 个会话、单并发，参数位于 Sidecar `.env` 的 `MEMORY_*` 配置。

`memory/pipeline.py` 分两阶段调用当前账号的模型配置：先从未处理的消息中提取带原文证据的候选，再与当前作用范围内的相关记忆比较，选择跳过、新增或合并。最多 6 条候选，低置信度、无法核验的引用和可识别凭证会被过滤；模型不具备工具执行能力。输入与合并上下文分别限制约 24000 字符，提取和合并模型可以各自覆盖。后台调用消耗模型额度，尚未纳入聊天单次运行的用量统计。

`memory/jobs.py` 在同一 SQLite 中保存任务租约、重试时间、输入消息摘要与来源会话引用，不复制完整聊天正文。模型调用不持有会话锁或数据库事务。成功后在同一事务提交记忆和已处理标记；重复扫描不会重复调用模型。失败最多尝试 3 次、指数退避，进程崩溃后租约过期可重新领取；修复配置后关闭再开启自动生成，可重新尝试失败任务。

提交前重新核验会话分支、活动状态、项目授权和记忆版本。用户在生成期间继续聊天、修改记忆或关闭自动生成时，过期结果丢弃。人工维护、停用、过期的记忆不自动覆盖；用户编辑自动记忆后转为手动维护。

本机存储中的读取和生成设置仍相互独立，默认开启；全局后台生成可通过 `MEMORY_AUTO_ENABLED` 配置，前端不再提供切换入口。删除会清理该记忆及其历史正文，保留不含正文的删除标记和归一化主题/内容摘要；并将删除时间作为旧消息补提取的截止线，保守地阻止此前所有聊天再次参与生成，避免换标题后重新记回已删除事实。删除后的新消息仍可提取其他主题；同名主题不会被后台自动恢复。

修改或删除只影响后续运行，已装配的模型上下文、审批检查点和旧聊天不会被改写。备份应包含本机记忆数据库。模型筛选和凭证脱敏并非完整的敏感信息检测系统，发布前仍应审阅自动生成内容。

### 本地语义索引

`memory/vectors.py` 复用方舟 `EMBEDDING_*` 配置生成标题和正文的向量。正文、范围、来源、版本仍在 `memories` 表，归一化 float32 向量以 BLOB 保存在同一 SQLite 的 `memory_vectors` 表，不存入云端数据库。生成向量时，文本会请求配置的 embedding 服务。当前每个账号最多 1000 条，过滤后在本机精确计算余弦相似度，无需额外向量数据库或 SQLite 扩展。

索引记录关联正文版本及模型空间指纹；修改记忆自动失效，删除记忆通过外键级联清理。旧记忆由后台每批最多 16 条补建，新生成记忆提交后也会尝试补建；模型配置变更或索引损坏会重新生成。模型请求不占用 SQLite 事务或会话锁，提交向量前核验正文版本，拒绝写回已删除或已修改记录。

`MEMORY_MIN_SIMILARITY` 默认 0.25，控制最低相似度；无相关结果不注入记忆。`MEMORY_RETRIEVAL_TIMEOUT_SECONDS` 默认 10 秒，限制每轮索引及召回的总等待时间；向量服务未配置、失败或超时后，回退到原有范围加载，已成功生成的索引保留供下次使用。读取关闭、过期、删除及版本变化会在模型返回后重新核验。`MEMORY_AUTO_ENABLED=0` 只停止聊天提取，不停止已有记忆索引维护。
