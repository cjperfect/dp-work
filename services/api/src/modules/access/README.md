# PyCasbin 角色权限

权限引擎使用 `casbin`（PyCasbin）；SQLAlchemy 在现有业务事务中持久化策略和审计。引擎只做角色/操作判断，数据归属、分享凭证和知识库范围继续由原业务模块检查，管理员不会自动获得其他用户文档。

## 内置角色

- `admin`：默认拥有平台管理及全部业务操作，可独立调整权限。
- `member`：默认拥有知识库、会议、协作和设备操作能力，可按需独立调整。
- `manager`：独立配置权限，不再继承 member；仍不扩大部门数据范围。
- `viewer`：默认提供只读知识库/会议、知识检索及本人设备连接，也可由管理员调整。

角色保存在 `users.role`，本期每人一个角色。注册仍固定为 member，禁止客户端注册或自行授予管理员。部门字段不构成授权来源，本期不增加部门共享或多租户模型。

## 使用接口

- `GET /api/access/me`：返回当前数据库角色及有效权限，供客户端显示功能。
- `GET /api/access/roles`：管理员查看内置角色、独立权限和权限目录。
- `GET /api/access/users`：管理员查看用户公开信息。
- `PUT /api/access/users/{id}/role`：管理员分配角色，正文 `{"role":"viewer"}`。
- `PUT /api/access/roles/{role}/permissions`：管理员替换任意角色的独立权限，正文 `{"permissions":["knowledge:read","meeting:read"]}`。角色之间不继承，变更只影响被编辑角色。

拥有 `access:manage` 的有效用户可以显式给任意角色授予或撤销管理能力；角色名称本身不提供隐式权限。角色调整与策略调整写入 `access_audits`，不记录凭证。管理操作使用事务级 advisory lock 串行化并重新校验操作者身份，防止并发相互降权；禁止通过角色分配或策略修改移除最后一位有效用户的管理能力；未分配给有效用户的角色授权不算可用管理入口。

FastAPI 通过 `get_current_user` 中的服务端路径映射检查现有知识库、会议与设备 HTTP 操作，新增接口可声明 `Depends(require_permission("knowledge:write"))`。归档同时需要 `meeting:archive` 与 `knowledge:write`。

WebSocket 不依赖 HTTP 鉴权依赖：会议/文档订阅在握手和推送前检查当前权限；CRDT 更新再次校验编辑权限，awareness 仅需读权限，分享链接不能绕过角色限制；设备连接握手及定期保活重新校验。RAG 范围授权使用时也重新检查用户当前搜索权限。

## 策略一致性

每次权限判断读取 PG 中的当前策略，PyCasbin 引擎按完整策略快照缓存，不缓存“某用户允许访问”的结论。无需等待 JWT 过期或 Redis 缓存过期，其他 API 实例下一次检查即可使用新策略；数据库故障直接失败，不回退到允许访问。管理变更提交后也通过既有 PG/Redis 通道发送 `access_changed` 事件。

本期采用小规模策略全量读取，优先保证撤权正确；数据规模增长后可增加策略版本与跨实例 watcher，而不是盲目缓存权限。权限检查之后已经开始的业务事务/排队任务不自动取消。

## 边界与验证

本模块保护云端 API、协作 WebSocket 和知识检索回调。桌面本机 Agent、文件工具和本地配置仍由现有本机 Harness/审批控制；云端 RBAC 不是恶意客户端无法绕过的本地执行沙箱。管理界面位于 `/admin/users`，也可通过 `/api/docs` 调用管理接口。

迁移：`pnpm migrate`，新增 `0025_rbac_policies`，初始化默认策略；现有用户角色不变。独立测试库验证示例：

```sh
TEST_DATABASE_URL=postgresql+asyncpg://.../专用测试库 .venv/bin/python -m pytest tests/integration/test_access_db.py tests/integration/test_meeting_records_db.py -q
```

## 前端管理入口

前端固定路由 `/admin/users`，菜单名称“用户与权限”。登录后请求 `/api/access/me`，仅当服务端返回 `access:manage` 时显示入口；进入路由前重新核验，未登录跳转登录页，无权限展示 403。账号切换/退出时清空权限，迟到响应不会恢复旧账号权限；窗口激活、重新联网及可见页面每 60 秒刷新权限。

页面支持搜索/筛选用户、调整角色和配置角色直接权限；所有角色和权限均可独立勾选，保存时校验至少保留一位有效的权限管理用户，提交前展示更改确认，后端业务错误保留在对话框中。后端仍是授权依据，前端隐藏入口不替代接口校验。

前端验证：`pnpm --filter @dp-work/web test:access`；构建与登录回归分别运行 `build` 和 `test:auth`。

业务页面已接入同一权限源：知识库/会议菜单按读取权限展示；新建与编辑文档路由要求知识库读写权限；会议查看路由仅要求读权限，具体操作分别检查创建、生成、分享、恢复和归档权限。源文档和解析文档只读时禁用编辑，清理/定时保存、录音和旧数据迁移在权限撤销后停止写入；后台订阅也按读取权限开关。归档界面同时检查目标知识库的读写权限，以便选择知识库。

Agent 的本地技能与普通聊天沿用原执行控制；知识库关联开关按读/检索权限启用，发起聊天时若无检索权限，不再传入知识库范围。云端继续重新校验授权，不依赖前端隐藏控件。

迁移 `0026_independent_roles` 将原部门负责人继承的成员权限复制为独立授权，与原有直接授权取并集，保留升级前的有效权限。回退迁移不删除已有授权，避免丢失升级后的人工配置。
