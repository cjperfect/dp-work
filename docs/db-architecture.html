数据库分工与同步方向

SQLite = 本地事实源（单文件，零依赖）· 向量检索（预留）

本地 SQLite
· 用户 / 部门 / 权限
· Agent / Skill 版本
· 聊天记录
· 会议 / 转写片段（定稿）
· 会议纪要
· 知识库资料（元数据）
权限模型只在服务端强制
桌面端 SQLite
· 实时转写（definite=true 落库 pending）
· 待同步队列（outbox）
· 草稿（纪要草稿 / 会话草稿）
· 本地缓存（配置 / 只读资料）
离线可用 · 断网不丢 · 恢复后自动同步
检索层 向量检索（预留）
· 知识库资料 → 切分 chunk
· 文本向量（embedding）
· 语义检索（RAG 召回）
· 附：资料元数据在本地 SQLite
向量在服务端 · 桌面语义检索走 API
同步方向
只读下行用户 / 部门 / 权限 / Agent / Skill 版本 / 知识库资料元数据→ 桌面本地缓存
上行转写片段（outbox → SQLite 定稿） / 会议 / 纪要SQLite pending → 幂等同步
双向往来聊天（本地草稿上行 / 服务端历史下行）
仅本地草稿 / 待同步队列 / 临时文本（不跨端）
示意：主键统一整数自增（离线生成的片段 / 纪要 id 先落前端本地，再同步至本地 SQLite 幂等对应）；权限检查在上行时由服务端执行；向量检索预留，随资料入库在 api 侧切分并生成向量。
